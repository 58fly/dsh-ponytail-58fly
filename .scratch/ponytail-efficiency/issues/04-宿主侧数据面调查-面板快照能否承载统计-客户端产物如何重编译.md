# 04: 宿主侧数据面调查：面板快照能否承载统计、客户端产物如何重编译

Type: research

Status: resolved
## Question

「统计数字怎么安全地到达客户端面板」这件事，在 0.2.2 宿主上到底有多少条路，哪条不依赖私有 API？

要回答：
1. `configForms` 的 form 快照能否承载只读统计：`form.set/unset` 与快照订阅的刷新语义、有没有「服务端主动推」的通道；如果统计只能随档位变化才刷新，那面板上的数字会是脏的——这一点必须给出确定结论与源码位置。
2. 宿主还有哪些客户端可读的服务面（`remote.settings` / 自定义 read 路由 / `commandUi` / session projection），各自的能力与门禁，逐个给出源码位置与是否可被第三方插件使用。
3. 若都不行：退路是「面板打开时请求一次 + 手动刷新按钮」，这条退路要声明什么代价（无实时性）。
4. 客户端产物构建链：`src/client/` 到 `lib/client.js` 的构建命令是什么、新增一个 `charts.tsx` 会不会自动进包、`window.__ModuleLoader__.load({...})` 形态是否会被 bundler 保持、产物大小现在多少、加 8KB 会不会触发仓库现有的检查门禁（`scripts/verify.mjs` 里有没有体积断言）。
5. 结论：选哪条路，写进 `## Answer`，并明确「不承诺实时刷新」还是「承诺」——这一句直接决定 05 的 UI 文案。

## Answer

**结论先行：面板打开时用 `ctx.get('connection').rpc.call(...)` 拉一次 + 面板内「刷新」按钮。明确「不承诺实时刷新」。** 下面 4 条路都实测过，只有第 2 条不依赖私有 API、不给用户埋坑。

### 1. `configForms` form 快照承载统计 —— 否决

- 快照形状 `{status:'loading'|'ready'|'unavailable'|'idle', value, base, user, revision, writable}`，见 `$H/dsh-client-ui-settings/lib/client.js`（`:1109` loading、`:1217` unavailable、`:1229` ready）。
- **刷新时机不可控**：form 只在 `ctx.remote.$on("settings/document-updated")`、`ctx.on("connection/reset")`、`ensure()/load()` 三种时机重读（`:1489` 的 effect）；`form.set/unset` 成功后只 `mirror.acceptView(response.value)` 折回自己这一份快照（`:1178`）。→ **没有插件可控的「服务端主动推」，统计不会因为 pre-step 计数变化而刷新。**
- **宿主没有干净的触发入口**：`$H/dsh-settings/lib/index.js:382 invalidate()` 会 `queueMicrotask(() => this.describe())`，但它唯一监听的事件是 `:336 ctx.on("app-boot/config-reload")`，该事件只在 `$H/dsh-app-boot/lib/index.js:4618`（配置重载流程末尾）emit。插件调用 `invalidate()` 属于跨层摸私有方法，且统计变化会引出一次全量 schema 重算。
- **塞进 schema 会被抹掉**（实测，/tmp 探针）：未声明的 `stats` 字段能过 schemastery validate，但 `projectForm`（`$H/dsh-settings/lib/index.js:141`）只保留 `schema.dict` 里声明的键，直接被丢掉；改成 `z.object({...}).volatile()` 后确实能进投影（探针输出 `{"defaultMode":"full","stats":{"managedTurns":12}}`），但 `volatileForm`/`isVolatilePath`（`:122`、`:153`、`:509-533`）把它当可写可重置字段：任何一次 `settings.write` 的 `strip()` 都会 `Reflect.deleteProperty` 掉 volatile 路径，用户点「重置」也清空。**统计会被日常写档位抹掉，这是不可接受的语义。**

### 2. `connection.rpc` read 通道 —— 采用

- 服务端：`ctx.connection.rpc.handle('/ponytail-stats', async (endpoint, payload, signal, peer) => …)`。注册的是 `{ kind: "prefix", path: channel }` 的 webServer 路由，带 Host/Origin 门禁（`$H/dsh-client-connection/lib/index.js` 的 `register()` 与 `admit()`）。
- 客户端：`ctx.get('connection').rpc.call('/ponytail-stats', 'snapshot', payload)`，自己拼 `${channel}/${endpoint}` 后 POST，**不经过 gateway**（`$H/dsh-client-connection/lib/client.browser.js:1212`）。
- 契约细节：只收 POST + `content-type: application/json`，body 为 `{type:'client-request', rpcId, method: endpoint, payload}`；返回 `{ok, value}`。通道名必须匹配 `CHANNEL_PATTERN = /^\/[A-Za-z0-9._~-]+$/`，endpoint 段必须匹配 `ENDPOINT_SEGMENT_PATTERN = /^[A-Za-z0-9_$.-]+$/`。
- 代价：`package.json#dsh.client.inject` 要加 `@deepseek-ai/dsh-client-connection`（宿主自带包，`$H/dsh-client-ui-skill`、`$H/dsh-client-ui-message-feedback`、`$H/dsh-plugin-manager` 都已依赖它）。浏览器宿主恒为 `interactions = "answer"`（`client.browser.js:1386`），`ctx.provide("connection", handle)` 在 `:1497`，因此 `ctx.get('connection')` 一定能拿到。

### 3. 实时推送（`ctx.remote.$on` / `$stream`）—— 不可用

- `$H/dsh-api-remotes/lib/index.js:21` 的 `API_REMOTE_FORWARDED_EVENTS` 是硬编码事件白名单，`:155` 由它独占注册事件源；`$H/dsh-api-gateway/lib/index.js:882 registerRemoteEvents` **每进程只允许一个源**，重复注册直接抛 `typert gateway: forwarded Remote event source is already registered`。→ 第三方插件无法新增实时事件。
- 自建 Remote 命名空间也不通：`requireStrictCodec`（`$H/dsh-api-gateway/lib/client.browser.js`）只认 `codec.mode === "strict"`，strict codec 由宿主树里不存在的 `@deepseek-ai/dsh-typert-generator` 生成（与 `docs/research/dsh-plugin-contract-0.2.2.md` 9.1 一致）。

### 4. 退路（已采纳为主路径）的代价

- 数字是「上次读取时」的。面板挂载时拉一次；面板开着时不会自己变新，必须点「刷新」；重连（`connection/reset`）后 form 会刷新，统计也可顺带重拉一次（可选）。
- **05 的文案必须写「上次读取于 …」并提供刷新动作，任何地方不得暗示实时。**

### 5. 构建链与门禁（全部核实）

- 命令：`pnpm build` = `tsc -p tsconfig.build.json && node scripts/build-client.mjs`。
- **新增 `src/client/charts.tsx` 会自动进包**：esbuild `bundle: true` 从 `src/client/index.ts` 入口起算，被 entry 链 import 的文件自动内联。
- **外壳形态被保持**：产物由 `scripts/build-client.mjs` 自己拼 `window.__ModuleLoader__.load({ id, factory: (require) => {…} })`，esbuild 只产 body，外壳不由 bundler 决定。
- 当前体积：`lib/client.js` **16322 字节**，gzip **4585 字节**。构建脚本只打印体积。
- **没有任何体积门禁**：`scripts/verify.mjs` 第 2 组（`:295-340`）只查「文件存在 / 是 ModuleLoader 外壳 / id 等于包名 / 无 `@wenaixi/` / require 的模块都在 HOST_MODULES 里」，没有字节数断言。加 8KB 不会触发任何检查。
- **两条会被踩到的门禁**：
  - 新层 `src/stats/` 必须登记进 `scripts/verify.mjs:386` 的 `LAYERS` 与 `ALLOWED_DEPENDENCIES`，否则分层矩阵检查会把它当 root 层放过（漏检）或报错。
  - 第 11 组「零垃圾承诺」（`scripts/verify.mjs:831-850`）用 `WRITE_APIS` 扫描 `src/**` 的写盘调用，**任何 `writeFile`/`rename` 都会报红**。这与地面已定的 Q12「落盘 `~/.dsh/ponytail-58fly/stats.json`」**直接冲突**——留给 02 原型票拍板：要么改 Q12（不落盘），要么在第 11 组开一个具名白名单例外并把理由写进 verify 注释。
- 客户端 require 的解析面（`$H/dsh-client-modules/lib/client.js`）：静态表 11 项 → `loadCache` → boot graph 行 → `factories`，解析不到抛 `client-modules: cannot resolve "X" — not a seed word, not a materialized module, and not a row in the boot graph`。→ 若在客户端直接 `require('@deepseek-ai/dsh-client-connection')`，必须同时把模块 id 写进 esbuild 的 `HOST_MODULES` 与 esbuild 的 external；更稳的写法是**用 `ctx.get('connection')` 取服务，不 import 那个包**。
