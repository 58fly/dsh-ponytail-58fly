# 05: 效率区块的视觉与信息架构：一屏内的图形化表达

Type: grilling

Status: resolved

## Question

「效率」区块长什么样，一屏内怎么排，用什么图形回答「它到底生效了多少」？本票要**问出并定下**下列判断，然后把结论落成 `docs/design/ponytail-efficiency-ui.md`：

1. 区块内的信息层级：谁是主数字（受管轮次？注入次数？），谁是副数字，哪些进「更多」折叠。
2. 图形选型：环形（注入率）/ 横向条（按档位轮次分布）/ 迷你折线（近 7 天趋势，是否需要——要就要持久化按天桶，会加一层数据）——逐项问清楚要不要，别默认全上。
3. 字阶与栅格：标题/主数字/说明文字各用哪个宿主字号 token，间距用哪档，卡片内边距；与现有档位区、诊断链的视觉关系（同级副标题还是次级卡）。只用 `--dsw-alias-*` 与官方 primitives，禁 `#hex`。
4. 基线标注的呈现：预估区间怎么显示（区间条？两行文字？），「基准推算」标签放哪，「比没用 ponytail 的情况」这句原话放哪，来源链接的可点性。
5. 空态 / 错误态 / 降级态文案：零数据、读不到持久化文件、`configForms` unavailable 三种情况下各显示什么。
6. 响应式：设置页窄栏（约 360–420px）下的换行与图表最小尺寸。
7. 「清零」按钮的位置与二次确认的措辞。

`docs/design/ponytail-efficiency-ui.md`：色板只列 token 名、字阶表、栅格与间距、图表尺寸与 SVG 结构草图（ASCII 或清单）、三态文案表、验收 grep 规则（禁 `#hex`）。

## Answer

**产出文件：`docs/design/ponytail-efficiency-ui.md`（11 节）。** 七问定案如下：

### 1. 信息层级（一屏三层）

- **主数字 = 受管轮次 `managedTurns`**：它是「插件到底管了多少」的唯一不用解释的数字。
- **同权重副数字**：注入次数、切档次数、`/ponytail-*` 调用次数、注入字节（格式化成 `≈ N KB`）。
- **不设「更多」折叠**：数据本来只有九个字段，折叠反而要用户多点一次才看到注入率——那正是本区块的主卖点。
- `受管轮次 − 注入次数` **不单独列**：由前两个数自然读出，多列一个「未注入轮次」只会招来口径质疑。
- `firstAt`/`lastAt` 面板只显示成「数据截至 HH:MM」，完整时间戳归命令侧。

### 2. 图形选型（逐项，不默认全上）

| 图形 | 定案 | 理由 |
|---|---|---|
| 环形（注入率） | **要** | 只有「注入 / 未注入」两个分量，一眼看出说出口的比例。直径 64px、笔画 8px、12 点起顺时针。 |
| 横向条（按档位分布） | **要** | 四档同轴的相对量，条形比饼图好读，还顺带回答「你在哪档待得最多」。条高 8px、圆角 `--dsw-radius-sm`、行距 6px。 |
| 迷你折线（近 7 天） | **不要** | 要按天分桶就得落盘，与 Q12′「不落盘」直接冲突；不落盘只能画本次运行，而一次运行通常不足一天，折线退化成直线，纯装饰。 |

- 空数据时**不画 0% 环**（那等于宣称「注入率 0%」，真相是「还没有轮次」）：只画空槽 + 数值 `0`。

### 3. 字阶与栅格

宿主没有字号 token，官方 primitives 用固定 px 阶，沿用同一套：主数字 20/28 权重 600；副数字 14/22 权重 500；说明与图例 12/18；极小注脚 11/17（`Tag` 同档）；标题继承现有 `<h3>`。数字一律 `fontVariantNumeric: 'tabular-nums'`（刷新时数字不跳）。区块内 `gap:12`，主行到图表 `gap:16`，卡片内边距 `padding:12`。

**与现有内容的关系：与「优先级诊断链」同级 `<h3>`，不套卡片、不加重边框**——面板已有两级标题，再加卡片会碎。分隔用 `borderTop: '0.5px solid var(--dsw-alias-border-l3)'` + `paddingTop: 12`（0.5px 与 `Tag` 边框一致）。

### 4. 基线标注：三行定值表，**不做区间条**

- 三行指标：`outputTokens −45% [−54%, −35%]`、`cost −26% [−36%, −16%]`、`time −41% [−49%, −32%]`。
- **拒掉 `loc` −53%、`gzip` −41%、`turns` −22%、`cheaperOnTasks 30/38`**：前两个没法归因到「本机这些轮次」，后两个是基准自身的统计量，不是收益。
- 不用区间条：条形会被读成「进度」或「确定性」，而这里是**别人家基准的范围**，文字区间最不容易被误读。
- 「基准推算」用 `Tag tone="quiet"` 放在第三层标题右侧；标题原话固定 `比没用 ponytail 的情况（基准推算）`。
- 出处行 11px：`基线：上游 39 任务 × 5 次 × 三臂，Claude Code + Opus 5.5 · ` + 链接到上游 `benchmarks/results/2026-10-07-agentic.md`（`--dsw-alias-link`、`target="_blank"`、`rel="noreferrer"`），**同一行必须带限定语**「这是上游基准，不是本机测量。」
- 系数与区间只从 `src/stats/baseline.ts` 读，面板里不出现任何裸系数。

### 5. 三态文案（逐字定稿）

| 态 | 显示 |
|---|---|
| 加载中 | `正在读取统计…`（12px，`label-secondary`，无骨架屏） |
| 空态（`managedTurns === 0`） | 主行 `本机运行期累计：还没开始计数` + 一句 `发一条消息就会开始记：每个经过 Ponytail pre-step 的轮次都算一次。`，图表只画空槽，第三层基准表照常显示（与数据无关） |
| 读不到（rpc 抛错/404） | `统计暂时读不到（宿主没提供这个通道，或插件刚重启）。` + `[重试]`；若有旧数字则保留并标 `数据截至 HH:MM` |
| 通道不支持（`connection` 缺失） | 同上一句，不加解释，**绝不把错误对象原文甩给用户** |
| 清零中 | 按钮 disabled，文案 `正在清零…` |
| `configForms` unavailable | 整块面板（含效率区）不出现，与现状一致，不新增降级 |

「还没开始计数」是正常态，「读不到」是异常态——两者文案必须可区分，且都不用感叹号和警告三角。

### 6. 响应式（窄栏 360–420px）

主行三数 `< 420px` 时纵向堆叠（不横向滚动）；环形与条形容器 `flex-wrap: wrap`（窄栏环在上居中、条在下满宽）；条形最小宽度 160px，低于此标签从 36px 收到 28px；基准三行的区间**换行不截断**（截断区间=骗人）；全块无横向滚动条。

### 7. 清零

位置：区块最后一行左对齐，`Button variant="outline" size="sm"`（与「清除用户层覆盖」同款）。文案 `清零统计`（不叫「重置」，避免与档位那个按钮混淆）。二次确认用官方 `Modal` + `RiskConfirmation` 语义：标题 `清零本机统计？`、正文 `受管轮次、注入次数、注入字节、切档次数和命令调用次数都会归零，无法撤销。配置和档位不受影响。`、按钮 `取消` / `清零`。成功后一行 `已清零，从 0 重新计数。`，不常驻。

### 8. 给 06 的额外约束

- 环形用 `<svg viewBox="0 0 64 64">` + 两条 `<circle>`（底环 `--dsw-alias-border-l3`、进度 `--dsw-alias-state-business-primary`），`stroke-dasharray="{ratio*175.93} 175.93"`（`2πr`, r=28），`transform="rotate(-90 32 32)"`。
- 横向条**用 div 不用 SVG**（无曲线，div 更短也更好测）。
- 四档**不用四种颜色**：同一条轴上的量，涂四色会被误读成四个类别，全部用 `--dsw-alias-state-business-primary` 靠长度区分。
- 06 若新增 primitives（`Modal`/`RiskConfirmation`），要同步扩 `test/client-wiring.test.mjs` 的 `STUB_MODULES`，否则测试会因 `Modal is not a function` 挂掉。
- `@deepseek-ai/dsh-client-connection` 目前**不在 devDependencies**，06 走 `ctx.get('connection')` 时推荐用 `unknown` 结构化断言而不是加依赖，保住「零新增依赖」。
