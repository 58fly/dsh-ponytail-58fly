### 缺口 B：组合层被 env 顶掉时，状态行说「无覆盖」（我认为这是真 bug）

证据：`src/l0/diagnosis.ts:236` 的 `overriddenBy: envInferred ? 'env' : patchRaw !== null && patchMode !== effective ? 'patch' : null`。`envInferred` 优先，所以 env 一命中它永远是 `'env'`——**组合层写了值、被 env 顶掉，这个事实在 `overriddenBy` 里根本表达不出来**。

但 `panel.tsx:424` 的兜底写法是 `OVERRIDE_TEXT[diagnosis.overriddenBy ?? 'fallback'] ?? '无覆盖'`。`'fallback'` 不在 `OVERRIDE_TEXT` 里（只有 env / patch），所以 `null` 一律落到「无覆盖」。于是：`base = { defaultMode: 'lite' }`、`value = { defaultMode: 'ultra' }`（env 顶到 ultra），`overriddenBy === 'env'` → 显示「被环境变量覆盖」，**这个是对的**。真正错的是另一种：`overriddenBy === null` 本身涵盖「组合层有值且它就是生效值」与「谁都没写」两种情况，面板都写「无覆盖」——前者要说的是「生效值来自组合层」。

- **选项 1（推荐）**：**不改 `diagnose()`**（诊断层契约是地图硬边界），只在状态行把判断扩一层：`overriddenBy === null` 时，若 patch 行 `state === 'hit'` 且其 `note === '这一值来自 profile 组合层，不是用户手写的。'`，写「来自 Profile 组合层」，否则继续写「无覆盖」。
  - 代价：面板要读 `diagnosis.rows[1].note` 做字符串比较——比读一个字段脆，但这句文案由 `diagnosis.ts` 拥有、14 条哨兵里 :73 已经把它钉死，改动会被测试挡住。
  - 收益：状态行不再对「组合层给了值」撒谎，同时零诊断层改动。
- **选项 2**：在 `Diagnosis` 上补一个 `patchOrigin: '用户层' | '组合层' | null` 字段——`diagnosis.ts:141` 已经算好了，只是没导出。
  - 代价：扩 `Diagnosis` 契约 = 动地图硬边界「`diagnose()` 契约零改动」，还要补哨兵。
  - 收益：面板不用做字符串比较，语义干净。
- **选项 3**：维持现状，把这条记成已知缺口。
  - 代价：状态行继续在一种情况下说错话。
  - 收益：零改动。

注意：缺口 B 的方案二会碰硬边界，我倾向方案一——但这是**你的边界**，我不替你破。
