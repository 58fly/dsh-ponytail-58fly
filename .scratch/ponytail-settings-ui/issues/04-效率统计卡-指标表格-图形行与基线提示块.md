## 缺口 A：零轮次时面板印「约 -45%」，命令层说「没有可推算的量」

实测（`node --input-type=module` 跑 `lib/stats/baseline.js`）：

| 输入 | `activeTurns` | `outputTokens.center` | 面板现在显示 |
|---|---|---|---|
| `managedTurns=0` | 0 | **0** | 「输出 token　约 0%　[0%, 0%]」 |
| `managedTurns=10, turnsByMode.off=10` | 0 | **0** | 同上 |

原因：`projectSavings` 返回的是**已乘过基数的绝对值**（`base * row.center`，base=0 时一律 0）；而面板 `BaselineRows` 拿它当比例再乘 100（`panel.tsx:749` `Math.round(row.line.center * 100)`）。命令层已经处理了这件事（`gain.ts:114-119` 先把绝对值除以 base 还原成比例；`gain.ts:150-152` 在 `activeTurns === 0` 时改成「还没有非 off 档位的轮次，所以没有可推算的量。」），面板没跟上。

两句都是实话但含义相反：「约 0%」读起来是「省不了钱」，真相是「还没有可省的轮次」。基线块开头三行还紧跟着「这是上游基准，不是本机测量」，进一步把误读做实。

**选项**

| # | 做法 | 代价 | 推荐 |
|---|---|---|---|
| A1 | 面板复用命令层判据：`activeTurns === 0` 时不画三行，改印那一句现成的话 | 要 import `projectSavings`（已在 `baseline.ts` 导出，零新依赖）；`BaselineRows` 签名从无参变带 `stats` | ✅ |
| A2 | 保留三行但把「约 0%」换成「—」 | 读者还得自己推为什么是横杠，且与命令层文案分叉 | |
| A3 | 不动，只在块里加一句免责 | 明知有假话还留着 | |

## 缺口 B：面板漏了命令层有的「推算基数」

命令层印 `推算基数：N 个非 off 轮次 × 每轮假定 800 输出 token。`（`gain.ts:152`，`ASSUMED_TOKENS_PER_TURN` 从 `baseline.ts:45` 读）。面板直接从「三行百分比」跳到「出处链接」，中间那个 800 没出现过。三行百分比的分母就是这个假设；不写出来，读者无法判断「约 -45%」是对什么量的 45%。

这也不只是补齐：`ponytail-efficiency-ui.md` §8 的诚实纪律要求「推算依据必须在同一屏内可见」。

**选项**

| # | 做法 | 代价 | 推荐 |
|---|---|---|---|
| B1 | 基线块里，三行之下加一行 11px tertiary 的推算基数说明，措辞与命令层同一句 | 基线块多一行（约 17px 高） | ✅ |
| B2 | 把基数塞进「方法论」链接的 `title` | 触屏与键盘都摸不到，等于没有 | |
| B3 | 不加，认为读者会去看命令 | 面板独立可读的目标破了 | |
