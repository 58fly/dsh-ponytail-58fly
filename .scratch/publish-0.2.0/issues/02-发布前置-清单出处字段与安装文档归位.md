# 02: 发布前置：清单出处字段与安装文档归位

**What to build:** 一个从没说见过这个包的安装者，打开说明文档就能照着一行命令装上，而不是先找到压缩包；包的清单里带上发版必需的出处字段，出了问题找得到地方；并且有一份可以照着走的发布清单——包括发出去之后发现错了该怎么办。

**Blocked by:** None（可立即开工）

**Status:** ready-for-agent

- [ ] 说明文档的安装段改成「按包名装」为主线，压缩包手工安装降级为离线 / 内网备选路径。
- [ ] 离线路径的已知边界写清楚：那条路下对等依赖不会被自动补装，需要提前备好。
- [ ] 清单补上发版必需的出处字段（仓库地址、主页、问题跟踪、作者），用包管理器官方字段名。
- [ ] 已验收的五个字段一个都不动：文件白名单、导出映射、宿主引擎区间、宿主对等依赖、宿主声明段。
- [ ] 发布清单文档可照着走：发布前确认包名与版本在 registry 上还不存在、发布入口只有包管理器的发布命令且必须吃发布前钩子、不拿试运行当验收、出事了默认不撤回而是发补丁版并让默认标签前进。
- [ ] 变更日志不新增版本段（0.2.0 已是当前内容）；署名信息各项必须为空。
- [ ] 质量门全绿：类型检查、构建、产物校验（含其自检）、技能校验、兼容矩阵、全部测试。
