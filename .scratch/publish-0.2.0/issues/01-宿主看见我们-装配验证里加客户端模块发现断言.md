# 01: 宿主看见我们：装配验证里加客户端模块发现断言

**What to build:** 跑一次装配验证，就能看到**宿主自己给出的判定**：它把本包认成网页平台的客户端模块、给出一个真实存在的客户端产物路径、模块图里有本包这一行。宿主没认的时候要按四种成因分别说清是哪一种，而不是只报一句断言失败。删掉客户端声明、把平台改成别的、删掉导出映射里的客户端入口——这三种破坏各让检查变红；恢复原样重新变绿。

**Blocked by:** None（可立即开工）

**Status:** ready-for-agent

- [ ] 装配验证跑完既有四段之后，输出里含宿主判定五项：模块图按包名能找到本包、按包名取客户端产物路径非空且文件真实存在、发现函数对该模块名返回非空、结果里平台是网页、结果里外部依赖是数组且其产物路径与前面取到的是同一个文件。
- [ ] 产物路径比对先做真实路径规约再比：临时目录短前缀与规约后长前缀的差异不得造成假红。
- [ ] 产物外壳判定为「文件里存在该外壳且标识等于包名」，不依赖它出现在第几行（实测在前两行注释之后）。
- [ ] 宿主登记服务要在装载器起来之后挂载；它对网页服务器是可选注入，树里没有网页服务器时必须静默通过而不是报错。
- [ ] 四种失败成因各有一句独立文案：声明缺失 / 平台不是网页 / 导出映射缺客户端入口 / 产物文件不存在。
- [ ] 反向自检覆盖三破一复：删声明、改平台、删导出入口各自变红，恢复后变绿。
- [ ] 留下「缺陷版先红、正确版后绿」两次运行输出并贴进本票。
- [ ] 既有四段断言与三形态安装验证不回归；装配探针自检仍全绿。
