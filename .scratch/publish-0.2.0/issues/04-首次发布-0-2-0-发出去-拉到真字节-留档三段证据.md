# 04: 首次发布 0.2.0：发出去、拉到真字节、留档三段证据

**What to build:** 0.2.0 真的出现在 registry 上，任何陌生人一行 `dsh plugin add dsh-ponytail-58fly` 就能装上；发布之后从 registry 拉回字节复验通过。整件事的「发布前六道门输出 / registry 上该版本的摘要与压缩包地址 / 复验输出」三段都要留档在仓里，别人能照着核。

**Blocked by:** #01, #02, #03

**Status:** ready-for-agent

- [ ] 发布前确认发布机上包管理器已登录、且该账号对包名有发布权（实测本机当前 `npm whoami` 返回 401，这一步会先卡住）；本票的收尾动作之一是把登录态与账号名留档（不写凭据本身）。
- [ ] 发布前确认这个包名与这个版本在 registry 上还不存在，留输出。
- [ ] 发布入口只有包管理器的发布命令，六道门原样吃到；文档与脚本里不出现跳过生命周期脚本的开关。
- [ ] 发布后 registry 上能查到 0.2.0，默认标签指向它。
- [ ] 从 registry 拉回的字节复验通过：摘要一致、装配四段、宿主发现五项。
- [ ] 三段输出（六道门、registry 元数据、复验）留档到仓内，路径写进本票。
- [ ] 署名信息各项为空；不做产地签名（当前不是版本控制仓库、没有远端）。
- [ ] 发布失败的处置写进发布清单：默认不撤回，改发补丁版并让默认标签前进。
