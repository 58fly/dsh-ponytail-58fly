# 06: 设置页补「打开配置文件」入口（需先查宿主是否提供打开文件原语）

**What to build:** 

**Blocked by:** None (can start immediately)

**Status:** resolved

## 目的

规格 00 遗留待定项（原文写「另立票」）：设置页缺一个「打开配置文件」按钮。本次重构明确没加。

## 为什么本次没做

`PonytailPanelProps`（面板 props）与 `slots.register` 的槽位参数里都没有「打开文件」这一项能力，宿主也没提供打开本地文件的原语。加按钮就得先扩宿主契约，属于跨进程能力，超出 UI 重构范围。本次替代做法：诊断链的路径全部用 `PathLabel` 渲染（可悬停看全文、可复制），能确认「改的是哪个文件的哪个字段」。

## 要先查清

1. 宿主的 settings 段或 slot 注册参数里有没有可用的 `openPath` / `reveal` 类回调（跑一遍 primitives 与 slot API 的类型定义）。
2. 宿主 shell 是否提供中立的「打开文件」命令（不是 web 端的 `location` 跳转）。
3. 都没有的话，是否接受「复制路径」作为最终形态——那就关票并把这个决定写进设计文档。

## 验收

- 三条查清并写进票面。
- 有原语则：卡片头加一个 `variant="outline" size="sm"` 的「打开配置文件」按钮，`disabled` 条件与写权限一致，点击调宿主回调。
- 无原语则：关票，把取证与「以 PathLabel 代替」的结论写回设计文档 `docs/design/ponytail-settings-ui.md`。

## 结论：做了，走「打开」这一条路，落地在 `6e1b102`（main，已推送）

票面三条待查都在本机实测过，逐条写结论：

**① 宿主有没有 `openPath` / `reveal` 类回调？没有。**
`node_modules/@deepseek-ai/dsh-client-ui-primitives/lib/types/` 全量只有 `clipboard.d.ts`（`writeClipboard(text): Promise<boolean>`）与 `use-clipboard-copy.d.ts`。在 `node_modules/@deepseek-ai/*/lib/types/` 全文 grep `openPath|reveal|openFile|openExternal` 只命中三处：`AnimatedRows.d.ts`（注释噪音）、`markdown/MarkdownText.d.ts:38`、`markdown/MarkdownDelegate.d.ts`。
其中 `MarkdownDelegate.openFile` 是 React context 作用域的：`MarkdownDelegateProvider` 包住的子树里才有实现，面板外层拿到的 `useMarkdownDelegate()` 是空 delegate，**不可用**。
路径显示侧：`PathLabel` 契约只有 `{ path } & Omit<HTMLAttributes,'children'|'title'>`，没有 `onClick` 能力，也接不上。

**② 宿主 shell 有没有中立的「打开文件」？有一条，只对会话工作区文件有效。**
客户端可注入的 `sidebarRight` 服务有 `openResource(address)`（`dsh-client-ui-sidebar-right/lib/client.js:2494`），地址语法是 `dsh-resource://file/session/<sessionId>/<路径>` 或 `dsh-resource://file/absolute/<路径>`（`dsh-util-workspace-path/lib/index.js`）。chat 的 `openFile` 就是走这条（`dsh-client-ui-chat/lib/client.js:15490`）。无会话时 `require()` 抛 `sidebarRight: no session surface is mounted`（:2919）。
该 helper 包**不在本仓的可依赖面**（`primitives` 没 re-export，`scripts/build-client.mjs` 的 `HOST_MODULES` 白名单里也没有），所以 `encodeSegment`/`encodePath` 各写了 3 行——与宿主同义（保留冒号给 Windows 盘符）。

**③ 「复制路径」这条退路没有真实路径可用，已砍掉。**
`cordis.patch.yml` 的绝对位置由宿主决定（`DSH_HOME` 或 profile 目录），仓库 `src/` 全文 grep 只命中 `src/config/priority.ts:46` 的展示字符串与 `src/l0/paths.ts:86` 注释，**服务端从不读这个文件**；客户端也拿不到 `process.env` / 家目录。复制一段猜出来的路径比没有按钮更糟，所以不做。

### 实现（`src/client/panel.tsx` + `src/client/index.ts` + `test/client-wiring.test.mjs`）

- `PonytailPanelProps.openConfigFile?: () => ConfigOpenResult`，`ConfigOpenResult = 'opened' | 'missing' | 'no-session'`。可选：不传就不挂按钮，不留死按钮。
- `ConfigFileAction`：`Button variant="outline" size="sm"`，文案 `打开配置文件`；点完在按钮下方贴一句回执（11px / 17px，`--dsw-alias-label-tertiary`）——三种结局各说各的原因。
- 接线在诊断卡的卡头动作位（`Card action`）：诊断卡此前这个位置是空的，档位卡的清除按钮与效率卡的刷新都没动。
- `index.ts`：运行时依赖从 `['configForms']` 扩成 `['configForms', 'sidebarRight']`（顶层 `inject` 仍只有 `slots`）。会话 id 取 `sidebarRight.mounted.getSnapshot()`，没有就直接返回 `'no-session'`，不去调会抛错的 `openResource`。
- 本仓没装 `dsh-client-ui-sidebar-right` 的类型包，按宿主各插件（如 `dsh-client-ui-settings/lib/types/client/config-form.d.ts:93`）的做法用 `declare module '@deepseek-ai/cordis'` 补一条最小声明，只写 `mounted` 与 `openResource` 两个成员。没有用 `as unknown as`——`pnpm run verify` 对此是硬规则。

### 遗留

- 真机浏览器没验：本会话没有打开 web UI 实际点这个按钮，只验到「地址拼得对、无会话时不抛错、服务缺席时按钮不挂」。侧栏真实渲染与「补丁文件不存在」的表现属于使用者现场才看得见的，留给日常使用观察。
