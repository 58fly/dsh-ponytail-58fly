# 06: 设置页补「打开配置文件」入口（需先查宿主是否提供打开文件原语）

**What to build:** 

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

## 目的

规格 00 遗留待定项（原文写「另立票」）：设置页缺一个「打开配置文件」按钮。本次重构明确没加。

## 为什么本次没做

`PonytailPanelProps`（面板 props）与 `slots.register` 的槽位参数里都没有「打开文件」这一项能力，宿主也没提供打开本地文件的原语。加按钮就得先扩宿主契约，属于跨进程能力，超出 UI 重构范围。本次替代做法：诊断链的路径全部用 `PathLabel` 渲染（可悬停看全文、可复制），能确认「改的是哪个文件的哪个字段」。

## 要先查清

1. 宿主的 settings 段或 slot 注册参数里有没有可用的 `openPath` / `reveal` 类回调（跑一遍 primitives 与 slot API 的类型定义）。
2. 宿主 shell 是否提供中立的「打开文件」命令（不是 web 端的 `location` 跳转）。
3. 都没有的话，是否接受「复制路径」作为最终形态——那就关票并把这个决定写进设计文档。

## 验收

- 三条查清并写进票面。
- 有原语则：卡片头加一个 `variant="outline" size="sm"` 的「打开配置文件」按钮，`disabled` 条件与写权限一致，点击调宿主回调。
- 无原语则：关票，把取证与「以 PathLabel 代替」的结论写回设计文档 `docs/design/ponytail-settings-ui.md`。
