## Problem Statement

Ponytail 的设置页面板现在是一块**没有视觉结构的调试信息墙**。开发者在里面要回答三个问题——「我在用哪档」「这档是怎么被选中的」「它到底管了我多少轮」——但页面把答案平铺在一起：

- **控件误用**：四个档位 `off/lite/full/ultra` 用分段控件呈现，可档位说明文字却直接堆在标题下方，读者会误以为那一段是在介绍「当前选中的标签页」，而不是解释单选配置本身。
- **模块边界模糊**：三个功能区块（档位、诊断链、效率）只用同级小标题加一条上边框分隔，滚动时看不出「这几行属于同一个功能」。
- **诊断链没有结构**：三层（环境变量 / Profile 补丁 / 内置兜底）被画成一串「状态标签 + 粗体名称 + 说明」的行内文本，优先级顺序、来源路径、取值、备注混在一行里；窄栏下路径被挤成多行，`cordis.patch.yml → ponytail-58fly.config.defaultMode` 这种地址根本读不出来。
- **状态标签含义在现场无人解释**：五种状态（生效 / 被覆盖 / 值非法 / 未设置 / 不可观测）在代码里有独立语气色，但页面上没有图例，读者只能猜。
- **效率统计是纯文本罗列**：五个数字加环形图加横向条混在一起，没有表头也没有单位说明；基线备注是 11px 的灰字脚注，读者看不出那是一句免责声明还是一条普通说明。
- **按钮不成体系**：同一页里出现裸按钮、次要按钮、内联二次确认按钮，视觉权重互相打架，读者分不清哪个是主操作、哪个是危险操作。

一句话：这不是「好不好看」的问题，是**调试信息读不快**的问题。

## Solution

把面板重构成**三段式开发者调试面板**：三张彼此独立的卡片，每张带小标题和统一内边距，页面标题只叫 `Ponytail`。

1. **档位配置卡片**：四个档位改成真正意义上的分段单选（语义上明确这是单选配置，不是视图切换），四段各自一句短说明，完整对照收进一个 `?` 悬浮帮助；下方一行状态行 `生效 full · revision 12 · 被环境变量覆盖`；「清除用户层覆盖」降为卡片头的次要按钮，用户层没有值时置灰。
2. **优先级诊断链卡片**：标题行下方先讲规则——「取值顺序 环境变量 → Profile 补丁 → 内置兜底，先命中的赢」，紧跟五个状态标签作为图例；往下是从上至下的三层步骤表格，列固定为「状态｜来源｜取值」，路径用等宽字体并可悬停看全文，备注在宽栏单列、窄栏移到行下方。
3. **效率统计卡片**：五个指标改成指标表格，环形图和按档位分布的横向条作为表格里的两个图形行保留；「刷新」在卡片右上，「清零统计」在卡片底部左侧；基线免责说明改成带左侧竖条的提示块。

风格是克制的开发者工具后台：没有渐变、没有 emoji、没有 C 端装饰，只保证调试信息一屏可读。

## User Stories

1. 作为一个在 `cordis.patch.yml` 里改配置却没生效的开发者，我希望诊断链能把「取值顺序」写在最前面，好让我知道该先怀疑哪一层。
2. 作为一个第一次打开这个页面的人，我希望每个状态标签旁边一眼能找到对应的图例，好让我不用读代码就知道「被覆盖」和「未设置」的区别。
3. 作为一个在窄侧栏里看面板的开发者，我希望长路径不会被硬切成两行乱码，好让我能完整确认改的是哪个文件的哪个字段。
4. 作为一个需要把路径贴给别人的人，我希望悬停就能看到并复制完整路径，好让我不用手动选中那串带箭头的地址。
5. 作为一个刚被环境变量悄悄改掉档位的人，我希望状态行直接写「被环境变量覆盖」，好让我不用去翻三个区块自己推断。
6. 作为一个想确认「我到底有没有写过用户层值」的人，我希望「清除用户层覆盖」按钮在我没写过值时是置灰的，好让我一眼知道这个按钮现在没有意义。
7. 作为一个不确定四个档位差别的人，我希望四段选项各自带一句短说明，好让我不点开帮助也能猜个八九不离十。
8. 作为一个想读完整对照的人，我希望有个 `?` 按钮悬停就展开四档完整说明，好让我不用去翻 `/ponytail-help`。
9. 作为一个用屏幕阅读器的人，我希望这个 `?` 按钮能被 Tab 聚焦并读出，好让我也能拿到同样的帮助内容。
10. 作为一个只想快速切档的人，我希望点击分段控件就立刻写入并给出「已写入 / 未写入」的明确回执，好让我不用怀疑到底写没写进去。
11. 作为一个担心误操作的人，我希望「清零统计」需要二次确认，好让我不会一不小心把运行期累计清零。
12. 作为一个想看懂效率数字的人，我希望五个指标各自有一行、带单位或说明，好让我知道「注入字节」和「注入次数」不是一个东西。
13. 作为一个想知道注入率的人，我希望看到 `96 / 128` 这样的比值而不是只有一个百分比，好让我能自己算。
14. 作为一个想按档位看分布的人，我希望横向条保留在表格里而不是被删掉，好让我还能一眼看出哪档用得最多。
15. 作为一个读效率数字的人，我希望基线的免责说明是个显眼的提示块而不是灰色小字，好让我不会把上游基准误当成我本机的实测。
16. 作为一个点「刷新」的人，我希望刷新按钮在卡片右上角，并且刷新时按钮变灰，好让我知道它正在拉数据。
17. 作为一个打开设置页的人，我希望三个区块各自是一张卡片，好让我滚动时知道这会儿在看哪个功能。
18. 作为一个读诊断结果的人，我希望三层顺序固定是「环境变量 → Profile 补丁 → 内置兜底」，好让我形成稳定的阅读习惯。
19. 作为一个排查「值非法被忽略」的人，我希望「值非法」这个状态用危险色并且备注写明「值无效，已忽略」，好让我立刻知道要改值。
20. 作为一个在明暗两套主题间切换的人，我希望卡片、图例、按钮在两种主题下都不失明，好让我不用切回亮色才能读。
21. 作为一个不想被营销话术冒犯的人，我希望页面上永远不出现「你省了 X」，只出现「基准推算」和区间，好让我知道这些数字的边界。
22. 作为一个看到「不可观测」标签的人，我希望图例里就有这一项，好让我不会把它当成加载失败。
23. 作为一个在小屏笔记本上看的人，我希望页面宽度小于 480px 时自动切紧凑布局，好让我不用横向滚动。
24. 作为一个读「效率统计」的人，我希望卡片标题就是这个正式名字，好让我在命令输出里看到「设置 → Ponytail → 效率统计」时能对上号。
25. 作为一个用 `/ponytail-gain` 命令的人，我希望它末行指向的路径和面板标题逐字一致，好让我摸过去的时候不会找不到。
26. 作为一个工程师，我希望这次重构不改变任何诊断数据、不删任何一行诊断信息，好让我之前记住的现象全部还成立。

## Implementation Decisions

**范围与不改动面**

- 只重写面板渲染层。诊断纯函数的分层、状态机、常量字面量**零改动**；图表的对外契约（环形入参、横向条入参）**零改动**。
- 不新增依赖。帮助提示、图例、卡片、提示块全部用已装的官方原语（分段控件、标签、悬浮卡、路径标签、按钮）加普通 `div` 拼出来——宿主原语里没有 Card，也没有帮助图标，`?` 用文本节点画。
- 不新增写操作面。面板的写能力仍然只有「写档位」与「清除用户层覆盖」两个，不引入语言切换等新控件。
- 不新增「打开配置文件」入口：面板 props 与槽位注册参数里都没有打开文件的能力，路径的可复制能力由路径标签组件提供。

**页面骨架**

- 标题只写 `Ponytail`，下面一句定位说明。三段按「档位配置 → 优先级诊断链 → 效率统计」排列，每段一张卡片。
- 卡片样式：二级背景色底 + 三级边框 0.5px + 中等圆角 + 12px 内边距；卡片头左侧是小标题，右侧是最多一个动作位。
- 颜色、字体、圆角一律走宿主主题变量：卡片底 `--dsw-alias-bg-layer-2`、边框 `--dsw-alias-border-l3`、警告竖条 `--dsw-alias-state-warn-primary`、等宽 `--dsw-font-mono`、圆角 `--dsw-radius-md` / `--dsw-radius-sm`。**禁止**使用不存在的变量名（例如 `--dsw-alias-surface-raised`、`--dsw-alias-state-warning-primary`）与任何写死色值。

**档位卡片**

- 分段控件保留现有 id 与写入语义。四段各带一句悬停短说明（一句内讲清「最轻 / 默认 / 最狠 / 关闭」的性格，不复述完整文案）。
- 四档完整对照放进一个 `?` 按钮的悬浮卡；`?` 必须可 Tab 聚焦、带无障碍名。
- 状态行是单行文本，用分隔符串起三个事实：当前生效档位（等宽字体）、配置 revision、覆盖关系（「被环境变量覆盖」/「被 Profile 补丁覆盖」/「被内置兜底覆盖」，无覆盖写「无覆盖」）。**不**在状态行里报用户层是否有值——那由按钮的禁用态表达。
- 「清除用户层覆盖」放卡片头右侧，次要按钮样式；用户层无值时禁用。

**诊断链卡片**

- 标题行下方一行规则说明 + 五状态图例；放不下时整体换行，不拆成两处。
- 图例与正文共用同一个标签组件与同一套语气映射：生效=success、被覆盖=warning、值非法=danger、未设置=quiet、不可观测=info。**不使用 emoji**。
- 主体是表格，宽栏四列「状态｜来源｜取值｜备注」，窄栏三列「状态｜来源｜取值」外加行下方小字备注（备注数据不得丢失）。
- 来源列的路径用路径标签组件渲染（单行、首部渐隐、悬停全文、可复制），禁止用 `word-break` 硬拆。取值列用等宽字体。
- 存在覆盖关系时，表格下方补一句谁盖住了谁。

**效率统计卡片**

- 卡片标题定名 `效率统计`（旧名「效率」作废）。卡头右侧依次是「数据截至 HH:MM」与「刷新」按钮；刷新进行中按钮禁用。
- 主体是表格，三列「指标｜数值｜说明/图形」。五行指标：受管轮次、注入次数、注入字节、切档次数、命令调用次数。注入率作为一行，数值列写 `注入次数 / 受管轮次` 的比值，图形列放环形；按档位分布作为一行，图形列跨列放四条横向条。
- 窄栏下只折叠「说明」列，图形列永不折叠；折叠后说明文字仍留在悬停标题里。极窄时环形与横向条各占整行。
- 基线免责说明是提示块：卡片内二级底色、左侧 2px 警告色竖条、12px 内边距；首行「这是上游基准，不是本机测量」，次行小一号写出处与方法论链接。
- 「清零统计」放卡片底部左对齐，保留现有的内联二次确认（不引入 Modal）。
- 加载中 / 空态 / 读不到 三种状态的文案与现在**逐字一致**，不改一字。

**响应式**

- 在面板根节点上测量自身宽度（`ResizeObserver`），`< 480px` 进紧凑模式；不用 CSS 媒体查询，因为设置页会被塞进侧栏与大屏分栏里，视口宽度不代表面板宽度。

**跨入口文案**

- `/ponytail-gain` 末行指向改为 `设置 → Ponytail → 效率统计`，与卡片标题逐字一致。
- `/ponytail` 命令输出**不改**：宿主侧服务只给出生效档位，拿不到面板那套三段投影，加覆盖提示就是猜。这是**已知信息缺口**，记在 Further Notes，另立后续票。

**设计文档**

- 旧笔记中被本次推翻的两处（「效率区不套卡片」「清零按钮的位置与样式」）标注「已被新规范取代」，新规范另起一份独立文档，写清卡片、图例、表格折叠、提示块与响应式的具体参数。

## Testing Decisions

**什么算好测试**：只测对外行为与可观测契约，不测内部函数拆分、不测内联样式字符串、不测组件树形状。这个仓里 UI 层没有 DOM（宿主无 jsdom），所以**不为渲染结果补 DOM 测试**——那会逼着引入一整层测试基建，与本次「零新增依赖」的边界冲突。

**一个测试接缝**（沿用现有，不新开）：

- **接缝 1：面板可渲染的面本身**。现有接线测试通过桩模块把打好的客户端产物从外壳里抠出来，验证注册项与注入面形状、两个写回调行为。本次只要求：面板组件在桩环境下**能被调用并返回非 null**（现有测试已经具备这个能力，只需确认重写后依然成立），以及写回调签名不变。

**不需要改的测试**（它们已经是本次重构的安全网）：

- 14 条诊断哨兵：三层恒在且顺序恒为 env→patch→fallback、五态判定、四个字面量一致性。本次重构不改诊断纯函数，这 14 条必须**一行不改继续全绿**——这是「没删诊断信息」最直接的机器证据。
- `verify` 第 10b 组「效率面板的诚实卡口」：扫 UI 面不写死颜色、不出现「你省了 / 实际节省」、不出现「实时」。卡片底色换成主题变量后这一组必须继续零命中。
- 全量测试与 `verify`：重构前后同样全绿。

**新增的自动化验收**（写进实施票的验证命令，不写进 DOM）：`pnpm verify` + 全量测试 + 客户端构建产物能生成、体积无异常增长。

## Out of Scope

- `/ponytail` 命令输出覆盖信息（需要先查宿主侧是否暴露配置三段投影；已立票 `05`，`needs-triage`）。
- 「打开配置文件」按钮（宿主没有打开文件的原语；已立票 `06`，`needs-triage`）。
- 语言切换控件。
- 为 UI 补 DOM 测试 / 引入 jsdom 或测试渲染器。
- 改变诊断算法、状态枚举、取值优先级。
- 改变效率统计的采集口径、基线系数、清零语义。
- 修改槽位注册键、配置命名空间、`ponytail-58fly` 相关 effect 标签（它们是地址不是品牌字）。
- 深色 / 浅色主题本身的 token 定义。

## Further Notes

- **已知信息缺口**：`/ponytail` 命令只能报生效档位，报不出「被谁覆盖」。根因是诊断的三段投影只在客户端可得，宿主侧服务只给一个生效值。要补齐需要在宿主侧找到等价的投影来源，属于宿主契约调查，不在本规格内。**跟进票：`05`（needs-triage）。**
- **`ponytail-58fly` 不是品牌残留**：它是槽位注册键与配置命名空间，改了面板就取不到配置。本次只收拾用户可见的品牌字样（页面标题），代码标识一律保留。
- **两份设计文档的关系**：旧笔记讲的是「效率区块与诊断链同级、不套卡片」，那是当时没有卡片需求的结论。本次需求变了，旧结论作废；新文档必须明确写「取代旧笔记的哪几节」，否则后来者会看到两份互相矛盾的规范。
- **定位说明措辞**：页面顶部那句定位说明要说清「这是给开发者看的调试面板」，不要写成产品介绍语。
