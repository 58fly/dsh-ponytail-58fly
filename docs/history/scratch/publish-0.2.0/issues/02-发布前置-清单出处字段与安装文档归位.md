### 票面没点名的两处真缺陷（已修）

**缺陷一：`docs/发布清单.md` 的复验命令跑不通。**
原写法 `node scripts/check-install.mjs --mode assemble --tarball <(npm pack dsh-ponytail-58fly@0.2.0)`，
实测两次都失败：`message: 'cannot copy a FIFO pipe: …/plugin.tgz'` / `syscall: 'cp'` / `errno: 22` / `code: 'EINVAL'`。
根因是 bash 进程替换给的是 FIFO，而 `scripts/check-install.mjs` 用 `cp` 把包拷进探针目录，`cp` 对 FIFO 报错。
发版后照着走必失败。改成先落盘再传路径（已实测 exit 0，输出「安装形态验证通过（mode=assemble）」）：

```bash
TD="$(mktemp -d /tmp/pt-verify-XXXXXX)"
npm pack dsh-ponytail-58fly@0.2.0 --pack-destination "$TD"
node scripts/check-install.mjs --mode assemble --tarball "$TD/dsh-ponytail-58fly-0.2.0.tgz"
```

文档里同时写明「不要写成 `<(...)`」以及为什么，避免下次有人再改回去。

**缺陷二：全部 `dsh plugin` 命令都缺 `--profile`。**
`dsh plugin` 的 `--profile <name>` 是 `requiredOption`（`@deepseek-ai/dsh/lib/bin.js:116-121`），实测缺少直接报
`error: required option '--profile <name>' not specified`。原文里 `README.md` 三处（:24 / :44 / :56）与
`docs/migration-from-wenaixi.md:32` 全都没写，照着敲必失败。全部补齐；`README.md:32` 补上 profile 名取值说明
（官方模板 `web` / `headless` / `acp` / `sdk` / `sdk-minimal`；`desktop` 由应用独占，命令行不接管）。

### 顺带纠正的两处口径

**「装完要手工把包名加进 `dsh.profile.bundles`」不准确。** `dsh plugin --profile <name> add <pkg>` 成功后，
`dsh-plugin-manager` 的 `reconcile()`（`lib/types/operations.js:96-137`）会对每个新增 dependency 检查
`manifest.dsh?.bundle?.patch`，本包声明了 `./cordis.patch.yml`，于是自动把包名 push 进 bundles 并 `saveManifest`。
实测：在一次性 profile 里跑 `dsh plugin --profile pt-readme-verify add dsh-ponytail-58fly`，装完的 `package.json` 是
`{"dependencies":{"dsh-ponytail-58fly":"^0.2.0"},"dsh":{"profile":{"bundles":["@deepseek-ai/dsh-base","dsh-ponytail-58fly"]}}}`。
→ README 改成「`dsh plugin` 会自动登记；只有绕开它直接 `npm install` 时才需要手工加」，并写明判据。

**发布清单的门数是七道不是六道。** `prepublishOnly` 在 01 票之后已串到七道（末尾多了 `node scripts/verify-release.mjs`），
而清单里「发版前」那段只列六道、且没带 `verify-release`。改成与 `package.json` 逐字对齐的七道。

### 附带发现：pnpm 12 的 `Agent skills awaiting approval`

装的时候 pnpm 12.16.1 会打 `Agent skills awaiting approval: dsh-ponytail-58fly`。查 pnpm CHANGELOG（12.11.0 段）：
`pnpm install` 会把直接依赖自带的 `skills/<名字>/SKILL.md` 链进**编码 agent** 的技能目录（`.claude/skills` 一类，由 `skills.dirs` 决定），
`pnpm approve` 前不链。实测：不批准的情况下，包内 `skills/ponytail/SKILL.md` 与其余五个技能目录全部照常在位（3739 字节），
DSH 的技能注册表读的就是包内 `skills/`，**不走这条链路**。→ 批不批准都不影响 Ponytail 可用；README 补一段说明，避免用户误以为技能没装上。

### 署名信息各项为空（第 6 条后半）

`signatures` 有两条，但那是 registry 对 tarball 的完整性签名，任何包都有，不属于「署名信息」。
