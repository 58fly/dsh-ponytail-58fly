# 01: 终点形态与分发：新包名另起还是接管同名；首版要不要带客户端 UI

Status: resolved
## Question

这是一张 grilling 票。定终点形态与首版范围，会直接决定后面 6 张 task 票的边界。

## 待拍板（每题给推荐答案，用户可改）

**Q1 包名与分发：新包名另起，还是接管 `@wenaixi/dsh-ponytail`？**
推荐：**新包名另起**（如 `dsh-ponytail-next` 或按用户偏好命名）。
理由：接管同名需要上游 npm 组织权限，且存量用户的 `engines.dsh` 锁死在 `<=0.2.1`，同名发布会把老用户直接推上不兼容路径；另起名可以做"平滑迁移说明 + 并存期"。代价是重新积累下载量（上游 1183/周）。

**Q2 首版是否带客户端 UI？**
推荐：**v0.1 纯宿主侧，v0.2 再加 UI**。
理由：客户端面是漂移区（四家同期实现 inject 集合与 slot 名全不同），先做 UI 等于把最不稳的部分放在最前面。且判据 6 要求"零 UI 也能完整工作"，纯宿主侧首版天然满足。

**Q3 档位切换的作用域？**
推荐：**全局档 + 会话级临时覆盖，重启回全局档**。
理由：上游的 `session-states.json` 持久化 100 个会话是它最大的一笔债（连带 175 行自愈链）。内存覆盖 + `agent/disposed` 清理能满足 99% 场景，且"重启回默认"是诚实语义（@mengyuly 的持久化文档也承认 session override 故意留内存）。

**Q4 与上游 DietrichGebert 的关系怎么写进 README？**
推荐：**明确声明"上游规则文本的移植，非官方"，并钉住同步的 commit**。
理由：避免"又一个 ponytail"的定位，同时把"我们跟得比谁都快"变成可验证承诺。

## Answer

四题定案，本条决议：

**1. 包名与分发**：新包名自建，`dsh-ponytail-58fly`，**不接管上游同名包**。理由：接管需上游 npm 组织权限，且同名发布会把存量用户推上 `engines.dsh <=0.2.1` 的不兼容路径；另起名可并存 + 给迁移说明。命名连带项（仓库名、`package.json#name`、`dsh.client` 模块 id、settings 命名空间、config 目录名、README）全链路统一；技能 id 前缀 `ponytail-*` 与命令前缀 `/ponytail` 保留不变。

**2. 首版范围**：v0.1 纯宿主侧，v0.2 再加客户端设置面板。判据 6「零 UI 也能完整工作」在纯宿主侧首版天然满足；客户端面是漂移区（四家同期实现 `dsh.client.inject` 与 slot 名全不同，0.2.2 里 `configForms` 归属仍在查），把它放在最前面等于用最不稳的部分承担发布风险。**连带：`#05` 客户端 UI 不再阻塞 `#11` 首版发布，降级为 v0.2 独立票。**

**3. 档位作用域**：全局档 + 会话级内存覆盖，重启回全局档。上游 `session-states.json` 持久化 100 个会话是 175 行自愈链的根因；内存 `Map` + `agent/disposed` 清理净删约 350 行。「重启回默认」是设计语义，写进文档而非当缺陷。

**4. 上游定位**：README 明确写「上游规则文本的移植，非官方」，并钉住同步的 commit。真上游 2026-10-29 仍在 push，规则文本变更不会通过版本号通知我们；把「同步得快」做成 CI diff + 钉住 sha 的可验证承诺。

由此 `#03` 的两条阻塞输入之一（包名）已确定，另一条是 `#09` 的 peer 区间。

四题定案：包名 dsh-ponytail-58fly、v0.1 纯宿主侧、全局档+会话级内存覆盖、README 声明上游移植并钉 commit。已并入地图 Decisions so far。
