# 05: 客户端 UI（可降级，v0.2 范围）：设置面板 + 档位快照通道

Type: task

Blocked by: 12, 07

Status: resolved
## Question

在宿主侧完全可用的前提下，加一个可降级的设置面板。

> **范围变更（#01 定案，2026-11-07）**：用户拍板 v0.1 纯宿主侧、v0.2 再加客户端 UI。**本票不再阻塞 #11 首版发布**，降级为 v0.2 的独立票；#11 在 v0.1 阶段按「零 UI」验收即可。

## 要做的事

1. **技术选型**：真 `.tsx` + tsdown/esbuild 打包（否决上游的字符串模板生成 `client.js`）。产物不入库。**入口契约按 `exports["./client"]` 声明，不按文件名硬猜**——宿主里有 3 个包（`dsh-api-gateway` / `dsh-client-connection` / `dsh-typert-registry`）的该字段指向 `lib/client.browser.js`（#12）。
2. **面板能力**：档位选择（4 档）、描述语言切换、**优先级诊断链展示**（"为什么我改了没用"）、一键恢复默认。**「单技能开关」本期降级**：宿主 `dsh-skill` 的 Config 没有 `enabled` 字段（`dsh-skill/lib/index.js:120`），官方无原语；面板只能展示「该技能属于哪个 provider、当前是否被 disable」，操作路径给「禁用整行 provider」或「改 `customSkillDirs`」，并明确标注这是 provider 级而非技能级（#12）。
3. **数据来源（两套通道，别混）**：
   - **客户端侧**：`configForms` 是**客户端服务名**（`dsh-client-ui-settings/lib/client.js:1270` `super(ctx,"configForms")`），`get(entryId)` 的参数是**宿主插件条目 id**，不是字段名；controller 面是 `getSnapshot()/subscribe()/set/unset/mutate(ops, expectedRevision?)`（`:1122/:1130/:1165`），宿主 0.2.2 已在 controller 内部做了 tail 串行队列 + `writeGeneration` + `pendingRevision` + recovery read，**上游 B-02 竞态在客户端侧已被宿主消掉，不要自己再写一遍串行化**。
   - **宿主侧**：服务名是 `settings`（`dsh-settings/lib/index.js:330`），**没有 `ctx.configForms`**。
   - **只读推导值**（当前生效档位、诊断链）：走 Typert 只读快照通道（`TypertRemoteService` + `@Remote('snapshot')`，0.2.2 已确认存在）。
4. **挂载点只用两个**：`settings.section`（设置页分区）与 `sidebar.right.pane.tab`（右栏 tab）。109 条 slot 全表在 `dsh-cordis-client-runner/lib/client.js:2606-7559`（索引 `:7705`），**上游用的 `plugins.bundle.config` 是插件详情页的 keyed slot，不是设置页，不要照抄**（#12）。
5. **视觉不自定义**：颜色/圆角一律用 `--dsw-alias-*` 变量与官方 primitives，不重定义主题 token。
6. **可降级**：UI 加载失败 / 客户端包缺失时，宿主侧功能零损失。所有 UI 能力都要有命令或配置的等价路径。
7. **档位通道不照抄上游**：当前生效档位一律从 Typert 快照读，不从 settings 反推；切档写 settings 后必须重新拉快照再渲染，不允许本地先改后写（上游 B-02 的根因就是本地乐观更新与宿主写队列打架）。

## 硬约束

- 客户端面是漂移区。`dsh.client.inject` 集合与 slot 名以 #12 的实测结论为准，不抄别家。
- **注册一律走 `slots.inject`，禁止裸 `slots.register`**：`inject` 在 slot 未声明时静默等待（`dsh-client-ui-renderer/lib/client.js:1393` `if (spec === void 0) return;`），slot 声明提交后自动补挂；裸 `register` 对未声明 slot 直接抛错。**降级只能选对通道，不能用 try/catch 探测**（#12）。上游 `whileServed` + `slots.inject` 的配对写法本身是官方姿势，可原样保留。
- **允许 UI 整块缺席**：`dsh.client.inject` 缺项不报错（`dsh-client-modules/lib/index.js:86-104` 中 inject 缺失合法），`arriveGraphRow`（`lib/client.js:791-794`）对取不到的包静默跳过，整包未激活只记 failures（`:547-564` 逐包隔离），页面不白屏。所以**不要为「UI 包缺席」写防御分支**，只需保证宿主侧功能独立可用。
- 档位切换必须能经官方 `/permission <preset>`（`dsh-permission-presets/lib/index.js:215-230`）与 `remote.settings.mutate` 等价完成；**UI 不是唯一入口**。
- 不在 UI 里做只有 UI 能做的事。

## 验收

- 面板能显示诊断链并指出被覆盖的那一层。
- 卸掉 UI 后，`/ponytail` 命令与配置文件仍能完成全部操作。
- 无自定义色值（`grep -c '#[0-9a-fA-F]\{3,6\}' ` 在客户端源码里为 0，或全部落在 `--dsw-alias-*` 之后）。

### 三、与票面的四处分歧（都是实测推翻了票面假设）

**① 「描述语言切换」在本仓没有第二种语言可切 → 不做旋钮。**
六个 `SKILL.md` 的 `description` 全是「英文首句 + `触发词：` 中文段」的**单份双语形态**（#08 已证不是中文改写、是上游英文原文快照），`src/config/schema.ts` 的 `locale` 字段至今**零消费者**（`grep -rn locale src/` 除 schema 定义与两处注释外无命中）。做一个没有消费端的旋钮，用户拨了它什么都不会变。处置：不放进 v0.2 面板，作为 #10 的后续（真要做就得给六个技能准备中英两份 description 并在 `provider.list()` 里分流）；本票不改 `schema.ts`，避免留下一个「看起来已实现」的字段。

**② 「一键恢复默认」改成「清除用户层覆盖」。**
宿主 `unset` 的语义是**回退到继承值**（`dsh-plugin-contract-0.2.2.md §7.3`），不是回退到 `DEFAULT_MODE`。继承值可能是 profile 组合层给的值，此时「恢复默认」的文案会撒谎。面板因此写「清除用户层覆盖」，并在返回文案里说「档位回落到继承值」——诊断链就在下方，用户一眼能看到回落到哪一层。按钮在 `snapshot.user === undefined`（本来就没有用户层）时禁用。

**③ 不新建 Typert Remote，票面第 3 条与第 7 条的措辞需要修正。**
票面写「只读推导值走 `TypertRemoteService` + `@Remote('snapshot')`」。实测：客户端**无法自造 Remote 命名空间**——`$H/dsh-api-gateway/lib/client.browser.js:2101-2109` 的 `requireStrictCodec` 要求每个参数的 codec `mode === 'strict'`，strict codec 只能由 `@deepseek-ai/dsh-typert-generator` 生成，而宿主打包树里没有这个包（`ls $H | grep -i generator` 为空）。手写 contribution 一律抛 `client api: generated Remote … has no strict codec`。
好在这条通道本来就不需要自造：`ctx.remote.settings.describe()` 返回的 namespace view 已经带 `value`/`base`/`user` 三段（`$H/dsh-settings/lib/index.js:413-468`），`ConfigForm` 把它包装成带 `subscribe` 的 store，正好就是「只读快照通道」。
第 7 条「不从 settings 反推」在实现上等于：`effective` 只读 `value` 投影，绝不用 `user` 段去猜——`user` 段只用于判断「有没有被覆盖」和诊断链的归属。

**④ 右栏 tab 未做，只做了设置页分区。**
票面说「挂载点只用两个」，是上限不是配额。`sidebar.right.pane.tab` 是 keyed slot（第三方的注册姿势是 `ctx.slots.register({ name, key: previewId, locale: NS }, Comp)`，见 `$H/dsh-client-ui-plan/lib/client.js:811-819`），而且要先用 `ctx.sidebarRightTabs.register({ id, kind, patterns, priority, canOpen, title })` 注册类型才能被打开——这需要额外注入 `sidebarRight` 与 `sidebarRightTabs` 两个客户端服务，并引入「tab 怎么被打开」的产品决策（自动开？给个按钮？）。本票的价值是「诊断链可见 + 可降级」，不是「多一个入口」，硬塞右栏 tab 只会把可降级面从 1 个服务扩到 3 个服务。留给 v0.3，且不必现在决定。

### 四条真发现（写进 `docs/research/dsh-plugin-contract-0.2.2.md` 第九章）

1. **两套 inject 的失败模式完全不同。** 客户端 `export const inject = [...]` 是硬依赖，服务缺席整条客户端条目不装载；`package.json#dsh.client.inject` 是模块图排序提示，缺项静默跳过（`arriveGraphRow`）。所以「可降级」的唯一正确写法是顶层只留 `['slots']` + 运行时 `ctx.inject(['configForms'], scope => …)`。
2. **`inject` 面的 `hooks` 会被改名。** `bindInjectSources` 把 `hooks: { snapshot }` 变成 `props.useSnapshot`（`standardHookPropName` 加 `use` 前缀 + 首字母大写）。写 `hooks: { useSnapshot }` 会得到 `useUseSnapshot`。`test/client-wiring.test.mjs` 第 5 条专门钉住。
3. **selector 必须是模块级常量。** 面板里的 `const IDENTITY = (snapshot) => snapshot` 首版写成内联箭头，`useSyncExternalStoreWithSelector` 每帧认为 selector 变了。这是 React 18 的经典坑，但在「renderer 拿 store 造 hook」这种间接装配下更难看出来。
4. **`slots.inject` 的 effect 挂在 renderer 的 fiber 上，不是调用方的。** 它在 `specDynamic(key) === undefined` 时直接 return（`$H/dsh-client-ui-renderer/lib/client.js:1393`），槽位声明后自动补挂、折叠后自动卸载。这就够了，不需要 `try/catch` 探测，也不需要额外的重试。

### 测试抓出的两个真 bug

1. `src/config/priority.ts` 的 `INVALID_PROBLEM` 没导出，哨兵测试第一次跑就 `SyntaxError: does not provide an export named 'INVALID_PROBLEM'`。已改成 `export const`，并注明「导出是为了让哨兵测试钉住客户端链的同名字面量」——**不抽公共常量**是刻意的：两边各自持有字面量，一边改了另一边不会自动跟着变，哨兵测试才会红。
2. `diagnose` 的兜底命中判据写错：原判据 `effective === DEFAULT_MODE && !envInferred` 在「用户层恰好写了 `full`」时让 patch 与 fallback 同时 `hit`，面板会同时点亮两行。改成 `!envInferred && patchMode !== effective`——判据必须是「补丁层没给出这个值」而不是「生效值等于兜底值」。

### 顺带修好的断链

`package.json` 的 `prepublishOnly` 引用了 `pnpm run check:matrix`，但 `scripts` 里从未定义它（`scripts/dsh-matrix.mjs` 存在且支持 `--check`）——发布前的六道门必在第 5 道失败。已补 `"check:matrix": "node scripts/dsh-matrix.mjs --check"`，实测输出「compat 矩阵覆盖 engines.dsh 区间内全部 15 个版本 ✓」。
