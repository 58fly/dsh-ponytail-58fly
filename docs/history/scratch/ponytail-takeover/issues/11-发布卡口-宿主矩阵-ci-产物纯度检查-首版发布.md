### 从第一性原理看这张票要证明什么

这张票不是「写三个脚本」，而是把「能装、装对、装干净」从主张变成**可复现的反对证据**。每一项都按「先找到会失败的样子，再证明现在不失败」的顺序做：

- 一个检查如果从来不会红，它就不是闸门，是装饰。
- 一个矩阵如果只覆盖两端，它测的是「两端能跑」，不是「区间内能跑」。
- 一个承诺如果只在作者机器上成立，它就不是承诺。

三种失败模式各有一道判据：**装不上**（矩阵 15 格 × 每格真装）、**装上了但装错**（纯度 / 清单卡口）、**装上了但脏**（三次快照差集 + 卸载探针）。

### ① 宿主矩阵：15 格穷举，每格真装配

- 本地逐版本实跑（`node scripts/set-dsh-version.mjs <v>` + `pnpm install --no-frozen-lockfile`）：0.2.0-rc.1 / 0.2.0-rc.2 / 0.2.1-alpha.1 / 0.2.1-alpha.5 / 0.2.1-rc.5 / 0.2.2-alpha.2 / 0.2.2-alpha.3 全部 **typecheck OK / build OK / 156 pass 0 fail**；其中 0.2.1-alpha.1 与 0.2.2-alpha.2 还跑通了 assemble 探针。跑完已还原到 0.2.2-rc.1 并重跑全套绿灯。

### ② 产物纯度：三块，仓库层与发布字节各查一遍

- 运行时依赖白名单只有 `@deepseek-ai/cordis` 与 `@deepseek-ai/schemastery`。

### ③ 清单卡口：三项都做双向

- tgz 内容 ↔ `files` 白名单双向校验（白名单里的必须在包里；包里不许有白名单外路径）。解包实测无 `src/`、`test/`、`.d.ts.map`、`tsbuildinfo`。

### ④ 零垃圾：三次快照差集 + 卸载探针

判据从「白名单认识某几个名」升级成「**装前 / 装后跑完 / 卸载后**三次快照（只收文件）差集为空」——白名单只能证明「我知道的那几个没出现」，差集能证明「没有我不知道的东西出现」。

- 装前 `new Set(await snapshotHome(profileHome))`，装后做差集，给 `/cordis.yml` 开口子（那是装配探针自己写的宿主配置，不开这口断言永远红）。
- `uninstallProbe` 用 `pnpm remove` 而不是 `rm -rf`：硬链/软链布局下 `rm` 会顺藤摸瓜删到仓库 —— **这条是踩出来的**，早期 selftest 真把仓库 `skills/` 清空过一次，已从 tarball 还原并改成「先复制到副本再动手」。断言三件事：node_modules 里插件目录消失、`createRequire().resolve(pluginName)` 必须抛错（解析器看不见才算真卸载）、`$DSH_HOME` 无残留。
- 三形态实测（tarball / link / assemble）全绿：`$DSH_HOME 内路径：/cordis.yml`、`卸载后 $DSH_HOME 内路径：（空）`。

### ⑥ v0.1 零客户端 UI：审计逼出来的一处真不一致

审计发现原实现说一套做一套：CHANGELOG 写「不会有设置页」，但 `package.json` 声明了 `dsh.client`、`src/client/index.ts` 又注册了 `plugins.bundle.config` 槽位，宿主 `dsh-client-modules` 会装载并渲染一张只有标题的卡片 —— 那不是零 UI，是半张 UI。

处置选了彻底那一条，不是改文档迁就代码：

- `src/client/index.ts` 的 `apply` 改为 `void ctx; void PonytailConfigPanel;`，不注册任何槽位（保留 `apply`/`inject` 导出契约，v0.2 恢复只改函数体）。
- `package.json` 整段删除 `dsh.client`（现 `dsh keys = ['bundle']`）。
- verify 的检查放宽为「可以不声明；一旦声明必须非空全名数组」—— 写错仍红，不写不红。
- 产物 `lib/client.js` 2617 bytes（原 2938），tarball 内 `grep -c plugins.bundle.config` = **0**。
- README FAQ / CHANGELOG / 迁移说明三处措辞同步为「插件管理器里不会出现任何入口（连空卡片都没有）」。
