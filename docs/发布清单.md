# 发布清单（dsh-ponytail-58fly）

这份清单照着走就能发一版，不需要回头翻别处。发布规范与 `58fly/dsh-stack` 共用一套：
**Git 先行，npm 后发**。原因只有一条：npm 上的版本不可撤销，GitHub 上的 commit 与 tag 可改可补。
顺序反了就再也补不齐——registry 上会永远留一个追溯不到任何 commit 的版本。

## 铁律

1. registry 上 `dsh-ponytail-58fly` 的**每个已发布版本**，GitHub 仓库里都必须有对应的 commit 与 tag。
2. GitHub `main` 的 `package.json` 版本号必须等于 registry 的 `latest`。
3. 发布入口**只有**包管理器的发布命令（`npm publish` / `pnpm publish`），
   并且必须吃 `prepublishOnly` 钩子。跳过生命周期脚本的开关不得出现在任何文档或脚本里。

## 发版前

```bash
# 1. 确认这个版本在 registry 上还不存在（回 404 才对）
npm view dsh-ponytail-58fly@0.2.0 version

# 2. 七道门全部走一遍（prepublishOnly 会再走一遍，这里是为了早点知道哪道红）
pnpm run typecheck && pnpm run build && pnpm run verify \
  && pnpm run check:skills && pnpm run check:matrix && pnpm test \
  && node scripts/verify-release.mjs

# 3. 工作区必须干净
git status --short
```

`CHANGELOG.md` 顶部必须有当前版本的小节，形如 `## [0.2.0] - 2026-11-08`。

## 发版

```bash
git add -A
git commit -m "release: 0.2.0 —— <一句话说明这次变了什么>"
git tag v0.2.0                      # tag 必须与 package.json 的 version 逐字一致
git push origin main
git push origin v0.2.0              # 推 tag 触发 .github/workflows/publish.yml
```

打 tag **之前**工作区必须干净，且 tag 指向的 commit 就是你要发的那个 commit。
之后只允许出现「不进包」的改动（`docs/`、`scripts/`、`.github/`、`.scratch/`）——
`scripts/verify-release.mjs` 会用 `git diff tag..HEAD -- package.json <files>` 精确判断这一点。

## 发版后

```bash
# 1. 三方对齐：GitHub tag / 本地 package.json / registry latest
pnpm run verify:release

# 2. 从 registry 拉回真字节，核对摘要，再走一遍装配断言与宿主发现断言
pnpm run verify:published
```

`verify:published` 问的是「**别人从 registry 装到的**那份字节能不能用」：它自己 `npm pack <名字>@<版本>`
拉到临时目录、比对 registry 的 `shasum` / `integrity`、把文件大小对一遍，再拿这份字节调
`check-install --mode assemble`，最后打印装配四段与宿主发现五项。它**不读**仓根任何本地 `.tgz`，
也不接受本地文件输入——正是为了不给你一个「拿本地包自证」的假绿。

版本还没发出去时它给一句「这个版本还没发布」并退非零，不甩 404 栈。

想手工拆开看每一段（排查时用）：

```bash
TD="$(mktemp -d /tmp/pt-verify-XXXXXX)"
npm pack dsh-ponytail-58fly@0.2.0 --pack-destination "$TD"
node scripts/check-install.mjs --mode assemble --tarball "$TD/dsh-ponytail-58fly-0.2.0.tgz"
```

`npm pack` 回在 stdout 打一行文件名，其余细节（`shasum` / `integrity` / `total files`）走 stderr。
**不要写成 `--tarball <(npm pack …)`**：进程替换给的是 FIFO，而 `check-install.mjs` 用 `cp`
把包拷进探针目录，`cp` 对 FIFO 报 `EINVAL: cannot copy a FIFO pipe`。先落盘再传路径。
不带 `--pack-destination` 时包会落在当前目录（`.gitignore` 里的 `*.tgz` 已忽略，不会污染 git）。

## 发现发错了怎么办

**默认不撤回。** 发补丁版让 `latest` 前进，把错的版本留在历史里。

理由：撤回（`npm unpublish`）会把那个版本从所有人的锁文件里抽走，装过它的人再 `npm ci` 直接失败。
72 小时内 `npm unpublish <pkg>@<version>` 技术可行，但代价是别人的构建红一片——
只有**已经泄露凭据、或包里被塞进了不该有的东西**才值得付这个代价，
而且即使是那种情况，首选也是发了补丁版之后再把旧版标记 `deprecated`。

发补丁版的完整步骤与上面一样，只把版本号换掉。

## 不拿试运行当验收

`npm publish --dry-run` 只回答「包里会有哪些文件」，不跑 `prepublishOnly`，
也不回答「装完能不能起来」。真正的验收是 `scripts/check-install.mjs --mode assemble`：
它把打出来的包真装进一个像 profile 的目录、真起 cordis、真断言技能面与切档行为。

## 凭据

仓库 secret `NPM_TOKEN`（npm 的 Automation token，账号 `58fly`）供 `publish.yml` 使用。
本机发布时用 `~/.npmrc` 里的 `_authToken`。两类凭据都**不入库**，也不写进任何文档。

令牌失效的表现与处置：`npm whoami` 返回 `401 Unauthorized` → 重新登录，
不要用「换个 registry」或「加 `--ignore-scripts`」绕过去。
