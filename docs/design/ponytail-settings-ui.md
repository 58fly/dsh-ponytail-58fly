# Ponytail 设置页 · UI 规范

> **本文取代 `docs/design/ponytail-efficiency-ui.md` 中「效率区不套卡片」与「清零按钮位置」两节。**
> 其余章节（图表选型、字阶、图表颜色、空数据口径、文案纪律）仍然有效，本文只写改掉的部分与新增的定案。
> 一句话：**三张同款卡片，卡片头一个动作位，紧凑靠量根节点宽度，不靠视口。**

## 0. 硬约束

| 约束 | 检查方式 |
|---|---|
| 不出现写死的颜色 | `grep -nE '#[0-9a-fA-F]{3,8}' src/client/*.tsx` 必须零命中 |
| 颜色只走 `--dsw-alias-*` | 新增颜色引用必须是下文列出的 token 名 |
| 不出现「实时」 | `grep -rn "实时" src/ docs/` 零命中；只有「刷新」按钮与「数据截至 …」 |
| 不出现「你省了 / 实际节省」 | 效率永远只说「比没用 ponytail 的情况（基准推算）」并给出处 |
| 注入率与分布不进 `<table>` | 见 §5，这是有意决定，不是漏改 |

## 1. 页面骨架

- 标题逐字 `Ponytail`（`<h2>`，不带版本后缀；版本号不进标题）。
- 标题下一行定位说明：`给开发者看的调试面板：…`（`<p>`，12px / 18px，`--dsw-alias-label-secondary`）。
- 三段顺序固定：**档位 → 优先级诊断链 → 效率统计**。顺序变了就是规范变了，不要各自调整。
- 三段都套同一种卡片；面板里不再有裸 `<h3>` 区块。

## 2. 卡片壳

| 属性 | 值 |
|---|---|
| 底色 | `var(--dsw-alias-bg-layer-2)` |
| 边框 | `0.5px solid var(--dsw-alias-border-l3)` |
| 圆角 | `var(--dsw-radius-md)` |
| 内边距 | `12px` |
| 卡内间距 | `gap: 12` |
| 卡头小标题 | `<h3>`，14px / 22px，600，`--dsw-alias-label-primary` |

- **卡头只有一个动作位**（右上角），空着就什么都不放：
  - 档位卡：`清除用户层覆盖`（`Button variant="outline" size="sm"`）。
  - 效率卡：数据截至 + `刷新`。
  - 诊断卡：`打开配置文件`（见 §4.1）。
- 标题旁的 `?` 不算动作位：它挂在卡片标题（`Card.title` 收 `ReactNode`）里，与标题同行。
- 卡头 `flexWrap`：紧凑时换行，宽栏下不换行。

## 3. 档位卡

- **分段单选**：四段 off / lite / full / ultra，展示名 `off · 关闭`、`lite · 最轻`、`full · 默认`、`ultra · 最狠`。
- **每段一句悬停短说明**（性格，不复述完整对照）：
  - off：待命：不注入，需要时手写 `/ponytail` 打开
  - lite：只说更小的那个选项，不动手
  - full：默认：最小完整改动 + 一条检查 + 风险说明
  - ultra：还要质疑需求，动手前先反驳
- **`?` 悬浮四档完整对照**：一行一档，标题 `四档对照`，下面档位名 + 完整说明。文案取自
  `skills/ponytail-help/SKILL.md`。**其中 off 一条取自该文件的「关闭」节，不是「档位」表**——
  档位表里根本没有 off 那一行，照抄会得到一句空话。
- **状态行单行**：`档位｜revision N｜覆盖关系`（全角竖线分隔）。
  - 覆盖关系三种：`被环境变量覆盖` / `被 Profile 补丁覆盖` / `来自 Profile 组合层`，其余写 `无覆盖`。
  - `来自 Profile 组合层`：补丁行 `hit` 且注脚是 `DIAGNOSIS_PATCH_FROM_PROFILE`——`overriddenBy` 是 `null`
    时它分不出「谁都没写」与「组合层给了值」，得补判这一层。
  - **没有「被内置兜底覆盖」这一态**：兜底生效时它就是生效层本身，写出来只会让人以为还有一层被盖住。
  - **补丁层没写过值时也不报覆盖**（`overriddenBy` 会是 `null`），见 §4 最后一条。
  - revision 缺失写 `revision 未知`。
  - 只读时补 `｜ 配置只读`（旧版就有）。
  - 紧凑时这一行允许换行，宽栏下强制单行（`flexWrap: nowrap`）。
- 写回执：`已写入` / `未写入` 两个 Tag + 一句话，失败不抛。

## 4. 优先级诊断链卡

- 规则句 + 五态图例**同一行**（`flexWrap: wrap`）：
  规则句 `取值顺序 环境变量 → Profile 补丁 → 内置兜底，先命中的赢`，图例按取值链顺序
  生效 / 被覆盖 / 值非法 / 未设置 / 不可观测。
- 表格三层恒画（env → patch → fallback），**不筛掉没值的层**：「哪层没设」本身就是要看的信息。
- 列：
  - 宽栏**四列**：状态 | 来源 | 取值 | 备注。
  - 紧凑**三列**：状态 | 来源 | 取值，**备注下移**成一行跨三列的副行（11px / 17px，`--dsw-alias-label-tertiary`）；
    副行同时在 `<tr title>` 上挂全文，与效率统计卡的做法一致。
- 路径用 `PathLabel`，**禁止 `word-break`**：路径断开就没法复制，只能整体换行（`overflow-wrap: anywhere`）。
- **td 保持 table-cell**：来源列里的「标签 + 路径」两行用内层 `<div>` 排，不要在 `<td>` 上写
  `display: flex`——那会让 td 脱离表格列宽计算，`tableLayout: fixed` 就失效了。
- 五态语气映射（`Tag` 的 tone，不用 emoji）：

| 状态 | 中文 | tone |
|---|---|---|
| hit | 生效 | `success` |
| shadowed | 被覆盖 | `warning` |
| invalid | 值非法 | `danger` |
| absent | 未设置 | `quiet` |
| unknown | 不可观测 | `info` |

- 补丁行的问题按**补丁层自身状态**分支，不按 `overriddenBy`：
  - `shadowed`（写了值但被盖住）：`你写的补丁层正被环境变量/更高优先级的补丁盖住：面板写入的是补丁层，读到的生效值来自别处。`
  - `invalid`（写了非法值）：`你写的「<原值>」不是合法档位，已被忽略，生效值来自更低一层。`
  - 其余（`hit` / `absent`）不补句。**补丁层没写过值就不说「被盖住」**——`overriddenBy` 只看生效值归属，
    用户层空、env 顶掉兜底时会误报「你改的补丁层」，判据必须落在补丁行自己的状态上。

### 4.1 打开配置文件（票 06）

- 卡头动作位就一个按钮：`打开配置文件`（`Button variant="outline" size="sm"`），
  打开的是 Profile 补丁 `cordis.patch.yml`。
- **只打开，不复制路径**：补丁文件的绝对位置由宿主决定（`DSH_HOME` 或 profile 目录下），
  服务端也没读过它，客户端拼不出来。复制一个猜出来的路径比没有按钮更糟。
- 实现走宿主的右侧边栏服务：`sidebarRight.openResource('dsh-resource://file/session/<sessionId>/cordis.patch.yml')`。
  会话 id 从 `sidebarRight.mounted.getSnapshot()` 取，`encodeSegment` 保留冒号（Windows 盘符）。
- 三种结局都要回一句话，贴在按钮下方（11px / 17px，`--dsw-alias-label-tertiary`）：
  `已在右侧边栏打开。` / `补丁文件还没生成：先在面板里存一次档位。` / `当前没有打开的会话，右侧边栏无处可放。`
- **服务缺席就不挂按钮**：`sidebarRight` 不在组合里时，`ctx.inject` 的子 fiber 起不来，
  回调不传，面板返回 `null`。宁缺一个按钮，不留一个点了没反应的按钮。

## 5. 效率统计卡

- 主体是**三列五行**的表格：`指标 | 数值 | 说明/图形`。
  - 数值列等宽、右对齐、`tabular-nums`、不换行（不许刷新时数字跳动）。
  - 五行指标：受管轮次、注入次数、注入字节、切档次数、命令调用次数，每行配一句说明。
- **注入率与按档位分布不是表格行，是表格下方的「标签 + 图形」块。**
  - **明确记录：它们不是 tr/td。** 原因：`Ring` 是手写 SVG、`BarList` 是一排 `<div>`，
    塞进 `<td>` 要么被 `tableLayout: fixed` 的列宽压成一条缝，要么得给 td 加 flex
    （见 §4 的同一条禁令），两者都会破坏表格。
  - 注入率：环形 + 右侧「注入率」标签与 `注入次数 / 受管轮次` 的等宽比值。
  - 按档位分布：左侧固定 72px 标签 + `BarList` 四条（off / lite / full / ultra 同色，靠长度区分）。
- **紧凑只折叠说明列**：图形列永不折叠；说明文字改挂到整行 `title` 上，悬停行内任意位置都能看到。
- 空数据：表格照画（全 0），下面换成两句话说明还没开始计数；**不画 0% 的环**。
- **基线提示块**：`background: var(--dsw-alias-bg-layer-2)` + 左侧 `2px solid var(--dsw-alias-state-warn-primary)`
  + `padding: 12`，内含标题「这是上游基准，不是本机测量」、基线出处与「方法论」链接、三行推算。
  - **限定语只印一次**：块首那句就是 `BASELINE_CAVEAT`，块尾不再重复（同一句连印两遍像两句不同的告诫）。
  - **推算基数必须可见**：三行之下加 11px / tertiary 一行 `baselineBasis(...)`，
    写清「N 个非 off 轮次 × 每轮假定 800 输出 token」。三行百分比的分母就是这个假设。
  - **非 off 轮次为 0 时不画三行**：改印 `BASELINE_NO_ACTIVE`（「还没有非 off 档位的轮次，所以没有可推算的量。」）。
    理由是 `projectSavings` 的绝对值乘过基数为 0，面板若照画会得到「约 0%」——那句话读起来是「省不了钱」，
    而真相是「还没有可省的轮次」。命令层一直是这个判据，面板照抄，两处从此同源。
- **清零**：卡底最后一行，**左对齐**，`Button variant="outline" size="sm"`，文案 `清零统计`。
  二次确认**内联**展开（不引 `Modal`）：`清零本机统计？` + 影响范围 + `取消` / `清零`。
  成功后一行 Tag + `已清零，从 0 重新计数。`。

## 6. 响应式

- 由**面板根节点**的 `ResizeObserver` 量自身宽度，`< 480px` 进紧凑模式。
- **不用 CSS 媒体查询**：设置页嵌在侧栏、分屏里，视口宽度 ≠ 面板宽度，媒体查询量错了对象。
- 量不到 `ResizeObserver`（老浏览器、测试桩）时降级成宽栏，不挂。
- 回调走 `requestAnimationFrame` 合并，避免同步 setState 触发 `ResizeObserver loop` 警告。
- `compact` 由面板量一次后作为 prop 往下传，卡片自己不测宽。

## 7. 跨入口文案

- `/ponytail-gain` 末行与卡片标题逐字一致：`面板里有图形版：设置 → Ponytail → 效率统计。`
- 设置页左侧导航条目只留品牌名 `Ponytail`。

## 8. 诚实纪律

- 不写死色值，只用 `--dsw-alias-*` 与官方 primitives。
- 不出现「实时」：只有「刷新」按钮与「数据截至 HH:MM」。
- 不出现「你省了 / 实际节省」：效率一律是「比没用 ponytail 的情况（基准推算）」+ 区间 + 出处 + 限定语。
- 空态、读不到、可观测性缺失各有各的完整句子，不用感叹号和警告三角。
